# ChatSpace — project status

Last updated: 2026-10-27

ChatSpace is a complete React + Vite + TypeScript messaging PWA on Supabase. Phases 1–7 have been implemented in code, including the visual system, private and group messaging, media, voice notes, calling, notifications, privacy and PWA installation. The remaining work is **verification against live external services** and a small set of explicitly optional or hardening items listed at the end.

> **Verification honesty:** the live Supabase project was reachable and had a valid signed-in session, but its database schema is **incomplete**. PostgREST returns `PGRST202` for the ChatSpace RPCs (`my_profile`, `my_conversations`, `presence_heartbeat`, `call_history`), so every signed-in screen shows its setup/error state instead of data. Authentication, storage, realtime, calls, LiveKit and push therefore still could not be exercised end-to-end. Only the checks under “What was actually run” are verified.

### Migration defect found and fixed (2026-10-26)

`0005` created `my_conversations()` returning `c.description` and `c.photo_path`, but both columns were only added by `0006`. Applying the files in order therefore always failed at that function with `42703: column c.description does not exist`, and because the SQL Editor executes a pasted file statement by statement, `0005` was left half-applied — which is exactly the mixed state the probes above show. `0005` now declares the two columns with `IF NOT EXISTS` and `0006` does the same, so the ordered set is valid and the pair is order-tolerant. A cross-file scan of all six migrations found no remaining forward references to tables or columns.

A second defect surfaced when `0006` was applied: one function header used a single `$` instead of the `$$` dollar quote, so `mark_conversation_unread` failed with `42601 syntax error at or near "$"`. Fixed, and `npm run db:setup` now fails the build if the combined script has an odd number of dollar quotes.

Recovery: [supabase/setup-all.sql](supabase/setup-all.sql) — generated by `npm run db:setup` from [reset-dev.sql](supabase/reset-dev.sql) + migrations + [backfill-profiles.sql](supabase/backfill-profiles.sql) — is one paste that installs everything from a clean schema. It is destructive for app data and meant for development. The individual scripts are still available for a manual, step-by-step recovery.

## Realtime and messaging defects found and fixed (2026-10-26)

Exercising the messaging workspace against the installed database surfaced five defects. All are fixed in code:

1. **No realtime subscription survived React StrictMode in development.** Supabase dedupes channels by topic — `channel('thread:x')` returns the instance that already exists — and adding listeners to a subscribed channel throws `cannot add postgres_changes callbacks … after subscribe()`. StrictMode runs every effect twice, so the second run reused the subscribed channel: messages, reactions, typing, presence, notification toasts and incoming call ringing silently never arrived, and screens only updated when something else triggered a refetch (a click or a navigation). Probed in the running app: two channels with the same topic are the same object, and adding a listener after `subscribe()` throws. Fixed with [`createChannel`](src/lib/realtime.ts), which gives every subscription a unique topic; all eight realtime subscriptions use it, guarded by a regression test.
2. **The chat list had no realtime at all.** Only an open thread subscribed to messages, so previews, ordering, unread badges and read receipts froze on every other screen. That subscription now lives in [`AppShell`](src/features/shell/AppShell.tsx) and refreshes the shared conversation cache app-wide.
3. **Realtime message rows are not enriched.** `postgres_changes` payloads contain table columns only, so a message arriving live had no reply preview and no attachments until a refetch. Incoming replies now fetch their joined row once, and attachment inserts refresh just the affected message instead of refetching every loaded page (which also lost scroll position).
4. **Every attachment-only message was labelled “Attachment”.** Reply quotes, the composer reply bar, the pinned bar and Saved messages now say Voice note / Photo / Video / File, plus “Message deleted” for tombstones. The reply-preview query now requests attachment kinds.
5. **Every message rendered a ghost reply quote.** `reply_to:messages!reply_to_id(...)` resolves the self-referencing relationship as one-to-many, so PostgREST returned `[]` for ordinary messages. An empty array is truthy: every bubble showed a reply block with the peer's name and “Attachment”. Replies are now fetched by id in a second, batched query and attached only when `reply_to_id` is set. Verified in the running app: the quote block is gone from ordinary messages and renders “Voice note” when a message really is a reply.
6. **Reactions, saves and pins silently failed.** They used PostgREST upserts (`ON CONFLICT DO UPDATE`), but `message_reactions`, `message_stars` and `pinned_messages` grant clients `select, insert, delete` only — no UPDATE. Supabase answered **403 `42501 permission denied for table message_reactions`**, and the optimistic pill was rolled back, so tapping a heart did nothing. These now insert and treat `23505` (already there) as success, which needs no new privileges.

### Verified live in the browser (2026-10-26)

With a real signed-in session against the installed database: a reaction was added from one tab and appeared in a second tab **without a reload**, then disappeared in the second tab when removed — the same `postgres_changes` path that carries messages, typing and calls. A voice-note reply now reads “Voice note” and ordinary messages no longer show a phantom quote. Cross-account (two different users) delivery and DELETEs on tables other than reactions still need a two-browser check; creating a throwaway account was blocked by the project's email rate limit (`over_email_send_rate_limit`).

## Design pass — chat surface (2026-10-27)

The conversation screen was reviewed in the running app in both themes and rebuilt where it read as heavy or unfinished:

1. **A photo sat inside an empty tinted frame.** Image and video messages were rendered inside the normal padded bubble, so a lone photo had a wide olive/yellow border and its timestamp floated on that frame. A single photo or video without a caption now renders edge to edge as the bubble itself, with the timestamp in a small translucent pill over the media (top-right for video, clear of the controls).
2. **Images were cropped.** `object-fit: cover` with a fixed height squared off portraits. They now keep their natural aspect ratio (measured: a 1586×992 upload renders at 384×240, exact ratio) and are capped at 24rem × 20rem.
3. **Bubbles had 1.5px outlines and loose padding.** They are now borderless with an 18px radius and a 5px tail, a soft shadow, a tighter meta row, and warmer/softer outgoing colours in both themes (dark outgoing was a muddy `#4D4211`).
4. **The composer stretched the full window width.** It is now capped to the same 54rem column as the messages, with a filled pill input, quiet icon buttons, one yellow send action, and no @-mention button outside group chats.
5. **The view drifted when media finished loading.** Images and videos change the scroll height after load, leaving the newest message below the fold. A `ResizeObserver` now keeps the view pinned while the user is at the bottom.
6. **The message actions trigger was a 17px dot.** Reply, react, save and delete all sit behind that “…” button, so it now has a 28px target with an 18px glyph (24px inside the media timestamp pill, 16px glyph).

Checked with the live DOM in the running app: no horizontal overflow at 1600, 1440 and 433 CSS pixels (`scrollWidth === clientWidth`), and the media bubble, its radius and its overlay measured correctly at each width. `typecheck`, `lint`, **15 test files / 47 tests** and `build` all pass.

## Required external configuration

1. Supabase URL + publishable/anon key in `.env`.
2. Apply migrations `0001` → `0006` in order (SQL Editor or `supabase db push`). If a previous attempt failed part-way, start from [supabase/reset-dev.sql](supabase/reset-dev.sql) on a development project rather than re-running a partial file.
3. Auth Site URL + redirect URLs (`/login`, `/reset-password`, `/app/**`).
4. SMTP/email templates and “Confirm email” for production.
5. Deploy `link-preview` for previews; `delete-account` for deletion; `ice-servers` + TURN for reliable calls; `livekit-token` + LiveKit secrets for group calls; `send-push` + VAPID + database webhook for push.
6. HTTPS static hosting with SPA fallback; rebuild after changing public env values.

## Known limitations

- **No end-to-end encryption.** WebRTC media is DTLS-SRTP in transit and LiveKit terminates media at the SFU; Supabase can read stored messages. Do not market this as E2EE.
- No live verification of any Supabase, TURN, LiveKit, email or push behavior in this environment.
- Realtime delivery is verified in one account across two tabs (reaction add/remove), not between two different users; cross-account messages, calls and notifications still need a manual two-browser check.
- Visual QA was partial: the capture tool scaled/cropped relative to the CSS viewport and failed while the window was covered. Layout was checked with DOM measurements; data-filled message, call and settings panels could not be rendered.
- The reference image was absent (`reference/` was empty), so the design follows the written brief.
- The production bundle is a single 1.46 MB chunk (409 kB gzip). It is within a workable range but has not been split or performance-profiled on a low-end device.
- Deleting a message hides attachments but does not delete the underlying Storage bytes; cancelled uploads can leave orphan objects.
- Search returns at most 20 results per query; the links gallery inspects the 60 most recent messages containing a URL.
- No automated RLS tests, E2E tests, accessibility/cross-browser audit or load test.
- Google OAuth is not implemented.
- Calls/groups have no screen sharing, recording, dial-in or moderation UI.
